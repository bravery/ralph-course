Ralph：自主式 AI 开发循环
01

Ralph 是什么？

理解自主式 AI 开发循环的核心思想

你描述需求，Ralph 实现它

想象一下，你只需要告诉 AI "我想给任务管理系统添加优先级功能"，Ralph 就会自动把这个需求分解成可执行的小任务，一个接一个地完成，直到全部实现。

💡 Ralph 的核心思想

Fresh instance, persistent memory（新实例，持久化记忆）

每次运行都是全新的 AI 实例（干净上下文），但通过 git 和文件系统"记住"之前的学习。

Ralph 解决的问题

🎯

小故事执行

将大需求分解成单次可完成的小故事，避免 AI 在长上下文里迷失

🔄

迭代推进

循环执行直到所有任务完成，自动处理依赖关系

💾

记忆沉淀

将发现的设计模式和代码库特性保存下来，供后续迭代学习

代码 ↔ 自然语言翻译

ralph.sh 核心循环
for i in $(seq 1 $MAX_ITERATIONS); do
# 启动 AI 实例
OUTPUT=$(cat "$SCRIPT_DIR/prompt.md" | amp ... || true)
# 检查完成信号
if echo "$OUTPUT" | grep "COMPLETE"; then
echo "Ralph completed all tasks!"
exit 0
fi
done
白话版解释

循环控制：Ralph 有一个最大迭代次数，默认 10 次。每次循环启动一个新的 AI 实例。

关键信号：当 AI 完成所有任务时，会在输出中放入 <promise>COMPLETE</promise> 这个特殊标记。

容错设计：|| true 确保即使 AI 命令失败，循环也会继续而不是崩溃。

优雅退出：收到完成信号后，Ralph 立即退出并输出成功消息，不会继续等待。

04

记忆机制

Ralph 如何在无状态 AI 实例间传递知识

Fresh Instance, Persistent Memory

这是 Ralph 最核心的设计哲学。每次迭代启动的都是全新的 AI 实例（Amp 或 Claude Code），没有任何之前的上下文记忆。但 Ralph 通过三个"记忆载体"让知识跨迭代传递。

💡 关键洞察

如果你让同一个 AI 实例连续运行多个故事，它会超出上下文窗口，变得越来越慢。Ralph 的"新实例+文件记忆"模式避免了这个问题。

记忆载体一：progress.txt

这是 Ralph 的"学习日志"，每次迭代都会在末尾追加新的学习内容。

progress.txt 内容示例
# Ralph Progress Log
# ====================
## Codebase Patterns
# --------------------
- This codebase uses React Hook Form
- All API calls go through /api/
- Components are in src/components/
# 2025-04-14 - US-001: Add priority field
- Added priority column to tasks table
- **Learnings for future iterations:
- Use Prisma's enum for priority: high|medium|low
- Always update frontend validation when schema changes
---
# 2025-04-14 - US-002: Display priority
- **Learnings for future iterations:
- TaskCard component handles badge display
- Priority colors: red=high, yellow=medium, gray=low
---
关键设计

只追加，不覆盖：progress.txt 只会在末尾添加新内容，历史永远不会丢失。

Codebase Patterns 区：开头的"Codebase Patterns"区域会由 Ralph 自动更新，汇总最重要的发现。

学习标记：每次迭代的"Learnings for future iterations"部分包含对后续迭代有价值的洞察。

提交记录：包含 git thread URL，供需要时追溯具体实现。

记忆载体二：AGENTS.md

这是"代码库指南"文件，用于记录项目级别的模式和惯例。

AGENTS.md 示例
# Ralph Agent Instructions
## Codebase Patterns
- Example: Use Prisma for database operations
- Example: All forms use React Hook Form
- Example: API errors are caught in hooks
## Project Structure
- src/components/ — UI components
- src/hooks/ — Custom React hooks
- src/lib/ — Shared utilities
- prisma/schema.prisma — Database schema
为什么 AGENTS.md 很重要

AI 友好：Ralph 会更新这个文件，当你问 AI "这个项目怎么构建"时，AI 会读取它。

人类友好：新开发者可以快速了解代码库结构。

上下文注入：AI 实例启动后，会先读 AGENTS.md 了解项目惯例，再开始编码。

记忆载体三：Git History

每次迭代的成果都通过 Git 提交保存，形成可追溯的历史记录。

🔀 Git 的工作

自动提交：每次故事完成后，AI 自动执行 git add . && git commit -m "feat: US-001 - Add priority field"

命名规范：提交信息格式固定：feat: [Story ID] - [Story Title]

历史可查：新实例通过 git log --oneline 了解当前状态

档案（Archive）机制

当开始新功能时，Ralph 会自动归档之前的运行记录。

05

聪明的技巧

Ralph 如何避免常见陷阱

故事拆分：小而可完成

Ralph 的核心理念：每个故事应该小到可以在一次迭代内完成。

prd.json 示例
"userStories": [
{
"id": "US-001",
"title": "Add deadline column",
"passes": false
},
{
"id": "US-002",
"title": "Show deadline in UI",
"passes": false
}
]
正确做法

单职责原则：US-001 只做数据库变更，US-002 只做 UI 显示。每个故事专注一件事。

依赖顺序：US-001 先做（数据库变更），US-002 后做（依赖数据库）。

避免这种情况：如果有一个故事叫"添加截止日期功能"，它可能同时涉及数据库、UI、验证、筛选，太复杂了。

验收标准：必须可验证

每个故事的验收标准必须具体、明确、可测试。

❌ 坏的验收标准
# US-003: Add deadline feature
"acceptanceCriteria": [
"Works correctly",
"Good UX",
"Users like it"
]
❌ 问题

"Works correctly" - 太模糊，怎么算正确？

"Good UX" - 主观判断，无法验证

"Users like it" - 需要用户调研，Ralph 无法验证

✅ 好的验收标准
# US-003: Add deadline field
"acceptanceCriteria": [
"Date column added to tasks table",
"Date picker shows on task form",
"Typecheck passes",
"Verify in browser using dev-browser skill"
]
✅ 改进

"Date column added" - 具体，可检查数据库 schema

"Date picker shows" - 明确，UI 功能具体描述

"Typecheck passes" - 可执行，有明确结果

"Verify in browser" - 为 UI 故事添加验证步骤

质量检查：永远不能绕过

Ralph 要求每个故事的验收标准必须包括质量检查。

⚠️ 关键规则

所有故事必须有：Typecheck passes

涉及测试的故事必须有：Tests pass

前端故事必须有：Verify in browser using dev-browser skill

错误处理：优雅降级

当 AI 命令失败时，Ralph 不会崩溃，而是继续迭代。

ralph.sh 中的容错代码
# 启动 AI 实例
OUTPUT=$(amp ... || true)
# 检查完成信号
if echo "$OUTPUT" | grep "<promise>COMPLETE</promise>"; then
exit 0
fi
容错设计

|| true：即使 amp 命令失败，也会继续执行，不会中断循环。

信号检查：只有收到 <promise>COMPLETE</promise> 才认为完成，失败只是跳过本次。

最大迭代保护：即使一直失败，也会在 MAX_ITERATIONS 次后退出，避免无限循环。

前端验证：dev-browser skill

对于 UI 相关的故事，必须在浏览器中验证。

前端故事必须包含
"acceptanceCriteria": [
"Priority badge shows on card",
"Typecheck passes",
"Verify in browser using dev-browser skill" /* 必须 */
]
为什么重要

Typecheck 无法检测 UI：TypeScript 能检查类型错误，但无法检查按钮是否可见。

浏览器验证确保可见性：确认 UI 组件正确渲染，用户可以交互。

避免空转：防止 AI 编译通过但 UI 完全没变化的情况。

测验：识别好模式

哪个验收标准最符合 Ralph 的要求？

Works correctly, Typecheck passes
Component renders, Typecheck passes, Verify in browser
Typecheck passes

1️⃣

2️⃣

常见问题 1：AI 卡住了

AI 可能陷入无限循环或长时间没有进展。

症状
# progress.txt 中看到：
# 同一条消息重复出现
"AI: Installing dependencies..." # 多次出现
"AI: Building project..." # 循环
原因和解决

可能原因：npm/yarn 依赖问题，缓存冲突，网络问题

解决方案 1：清理依赖：rm -rf node_modules && rm package-lock.json && npm install

解决方案 2：检查网络连接，重试

解决方案 3：在 prd.json 中减小任务范围

常见问题 2：Typecheck 失败

AI 修改的代码有类型错误。

progress.txt 中的错误
# Typecheck: FAILED
error TS2322: Type 'string | undefined' is not assignable to type 'string'
# src/components/TaskCard.tsx:45
如何帮助 Ralph

方法 1：AI 通常会自动修复类型错误

方法 2：如果反复失败，可以更详细描述要求

方法 3：检查 AGENTS.md 是否有相关编码规范

方法 4：手动修复并提交，让 Ralph 继续下一个故事

常见问题 3：验收标准未完成

故事标记为完成，但验收标准没有全部满足。

prd.json 状态
"userStories": [
{
"id": "US-003",
"title": "Show priority badge",
"passes": false // 标记为未完成
}
]
为什么发生

原因 1：AI 认为已完成，但实际未通过所有验证

原因 2：验收标准描述不清晰，AI 理解有误

原因 3：测试/Typecheck 通过了，但 UI 没验证

解决方法：检查哪些验收标准未满足，添加更具体的描述

常见问题 4：git 冲突

当多个功能分支同时开发时可能发生冲突。

症状
# AI 提交时遇到错误
"error: merge conflicts"
"src/utils/api.ts contains conflicts"
如何处理

AI 无法自动解决冲突：需要人工介入

步骤 1：查看 conflict markers <<<<<<< HEAD

步骤 2：手动编辑文件，选择保留哪个版本

步骤 3：标记冲突已解决：git add 文件名

步骤 4：完成合并：git commit

预防：使用更小的故事，减少同时修改的文件数量
